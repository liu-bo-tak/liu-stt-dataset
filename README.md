# QA Knowledge Base Dataset

Цей репозиторій містить зібраний датасет матеріалів для QA-інженерів, а також інструмент (ETL-пайплайн) для його автоматизованого наповнення.

## Структура датасету

У цій гілці реалізовано підхід **"by-topic" (за темами)**. Дані з різних джерел об'єднуються та сортуються за предметними категоріями, що базуються на стандартах (наприклад, ISTQB).
*Запланована альтернативна гілка реалізуватиме підхід **"by-source" (за джерелами)**, де структура копіюватиме оригінальну ієрархію сайтів або авторів.*

Поточна структура (гілка by-topic):
- `data/` 
  - `sdlc/`
  - `api_testing/`
  - `automation_tools/`
  - ...та інші предметні категорії.

## Інструмент збору (`tools/pipeline.py`)

Для автоматизації збору використовується власний ETL-скрипт, який працює у три етапи:
1. **Discover:** Збір посилань (`raw_discovery.jsonl`).
2. **Classify:** LLM-аналіз (Gemini API) через `google-genai` та `pydantic`. Використовується механізм Structured Outputs (`Enum`) для жорсткого мапінгу статей на існуючі тематичні категорії. Алгоритм ковзного вікна запобігає блокуванню API (ліміт 5 запитів/хв).
3. **Download:** Асинхронне завантаження (`httpx`), очищення HTML від реклами/навігації (`BeautifulSoup4`) та збереження у Markdown (`markdownify`).

### Залежності та запуск
Для етапу класифікації потрібна змінна середовища:
`export GEMINI_API_KEY="ваш_ключ"`

Запуск пайплайну:
```bash
python tools/pipeline.py -h
```

## Наступні кроки
- Додавання підтримки парсингу PDF (PyMuPDF) та DOCX (python-docx). Усі нові дані будуть органічно вплетені в існуючі тематичні категорії.
